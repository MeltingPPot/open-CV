## 摘要

多模态大语言模型（MLLM）的兴起推动遥感智能发生了新的范式转变，即从“看”走向“行动”。尤其是，OpenClaw 风格的框架展现出一种很有吸引力的能力：自主操作大量遥感图像处理工具，执行复杂任务。

现有遥感智能体在调用工具时采用被动选择范式，依赖完整工具注册（Flat）或检索增强生成（RAG）。然而，面对规模庞大、来源多样且彼此异构的遥感工具生态，这些被动机制很难在整个任务推理过程中动态平衡“上下文负担”和“工具集完整性”，因而存在内在局限：完整注册会在长流程任务中造成上下文空间不足；RAG 检索则可能在关键步骤漏掉重要工具。

为突破这些瓶颈，本文重新定义工具选择范式，主张智能体应当成为工具空间中的主动探索者。基于这一观点，我们提出一种新的遥感智能体架构 RS-Claw。它在工具端利用 Skill 封装技术，对工具说明进行层次化组织，使智能体能够按需进行顺序决策：首先只阅读工具摘要，选择相关的技能分支；随后动态加载并阅读详细说明；最终完成准确调用。

这种主动范式不仅显著释放了智能体的上下文空间，也有效保证了长流程推理中关键工具的准确命中率。在 Earth-Bench 基准上的系统实验表明，RS-Claw 的主动探索机制能够有效过滤语义噪声并大幅释放推理空间，输入 token 压缩率最高达到 86%；在多种复杂推理评测中，它整体优于现有的 Flat 和 RAG 基线。

**关键词：**遥感智能体、大语言模型、工具选择、主动工具探索、层次化技能树。

> **零基础提示：这篇论文不是在发明新的图像识别网络。**它研究的是：当一个 AI 面前有 104 个遥感工具时，怎样让 AI 在需要时找到正确工具，又不必把 104 份详细说明一直背在上下文里。可以把它理解为给 AI 设计一套“先看楼层索引，再看书架目录，最后拿具体书”的图书馆导航系统。

# I. 引言

近年来，大语言模型在意图理解、自主决策和工具使用方面持续进步。研究人员据此开发了配备专用工具集的 LLM 智能体，使其能够自主执行复杂推理任务。这些智能体可以解析自然语言指令，通过自主规划和调用外部工具完成任务。在通用领域，OpenClaw 等智能体已经展现了通过动态调用工具完成任务的巨大潜力。

借助这种自主执行能力，遥感领域的研究人员也开始让智能体按照不同的定制要求处理遥感影像。例如，RS-Agent 通过任务分解和多工具协同调度，自动执行场景分类、视觉问答和目标计数等任务；Earth-Agent 则集成了指数计算、目标识别和统计分析等领域工具，以支持多模态、定量的时空推理和科学分析。

大多数现有遥感智能体沿用了通用领域常见的“完整工具注册（Flat）”范式：把所有候选工具的功能说明直接拼接进系统提示。然而，遥感数据处理流程复杂，多源异构数据快速增加，智能体需要拥有不断扩展的大型工具库，其中可能包含 QGIS、GDAL、Google Earth Engine 和 Orfeo ToolBox 等系统中的数百种功能。面对如此庞大的工具集，传统 Flat 范式不可避免地造成上下文瓶颈，并在推理中引出两个关键问题。

1. **长流程任务的推理空间受限。**以 Earth-Bench 为例，仅注册 104 个专业遥感工具及其参数说明就要消耗 20K 以上 token。即使先进模型支持更长的上下文，冗长的工具说明仍会占据很大空间，挤压智能体保存中间状态、多步试错和执行 ReAct 推理所需要的上下文。
2. **多源工具空间中的语义混淆。**不同传感器具有不同的物理机制和算法，但大量工具说明在文字上又很相似，这会产生大量“语义噪声”。模型因此容易出现注意力失焦和“遗失在中间”现象；在解析用户意图时，也更容易发生“工具幻觉”，即选错、编错或混淆工具。

> **零基础提示：上下文可以看作 AI 的工作台。**工具说明、中间文件名、计算结果和思考过程都要放在这张工作台上。把 104 本说明书全摊开，会让真正需要计算的空间变少；名称相似的工具还会互相干扰。

为缓解 Flat 带来的上下文瓶颈，已有研究主要探索基于外部检索增强的工具注册方式。此类方法先从大工具库中筛出一部分候选工具，再开始执行任务，因此能在一定程度上减少工具说明占用的上下文，例如 ToolReAct。然而，这种方式在遥感场景中仍有明显局限。

遥感任务经常包含多个阶段，所需工具还会随着中间状态改变。只根据最初的问题描述和表层语义相似度进行一次检索，很难覆盖后续推理阶段所需的所有关键工具。因此，RAG 虽然减轻了上下文负担，却可能以牺牲工具集完整性为代价。在大规模工具空间中，它很难同时保证上下文效率与多步推理的完整性。

现有方法因此仍难以同时平衡探索效率、推理完整性和系统可扩展性。我们认为，智能体调用工具的方式应当更接近人类认知：获取工具既不应是全局静态的被动检索，也不应是盲目的代码生成，而应当是由任务驱动、立足当前上下文推理、按需发现工具的主动探索过程。

为实现这一机制，本文从根本上重构智能体的工具端架构，提出 RS-Claw。受“渐进式披露”概念启发，我们不再使用扁平工具列表，而是借助专家知识，把大量遥感工具按语义封装成“技能”，构建结构化的层次技能树。我们进一步把发现和选择工具建模为智能体自主执行的顺序决策过程。工具探索不再由外部预设程序完成，而成为智能体动作空间中的一种内在动作；智能体可以在技能树中逐步搜索，并动态加载所需信息。

这种主动探索范式解决前述两项问题。第一，按需加载工具把上下文消耗从全局的 \(O(N)\) 降为局部的 \(O(K)\)，为维护复杂地理空间中间状态和多步逻辑推理释放空间。第二，由意图驱动的层次化探索会在决策路径早期过滤无关信息，从而减少多源工具空间中的语义噪声，缓解注意力失焦和工具幻觉。

### 本文的主要贡献

1. 我们为遥感智能体的工具选择提出一种新的视角。受人类认知逻辑启发，我们把工具选择重新定义为“主动探索”，使智能体由被动接收工具转变为在结构化工具空间中主动探索。借助这一转变，我们系统分析并处理 Flat 范式下推理空间受限和语义混淆的问题。
2. 受渐进式披露启发，我们在工具端设计层次化技能树，并把工具选择动作纳入智能体的自主顺序决策过程。智能体由此能按需动态加载工具子集，既释放推理上下文，又过滤多源工具集中的语义混淆和信息噪声。
3. 我们在 Earth-Bench 上进行了系统实验。RS-Claw 在全部模型和评测模式中整体优于 Flat 与 RAG。以 Qwen3-32B 的自主规划（AP）模式为例，RS-Claw 比 Flat 的准确率提高 12.45 个百分点；其每轮输入 token 明显下降，整题输入 token 的压缩率最高达到 86%。消融实验和扩展性实验进一步验证了结构设计的合理性与鲁棒性。
 
### 图 1：工具选择范式比较

- **被动范式。**Flat 把全部工具全局注入上下文，可能导致上下文溢出并严重压缩推理空间；RAG 虽能释放部分空间，却可能在长流程推理中漏掉关键工具。
- **主动范式。**RS-Claw 把智能体定义为主动工具探索者。智能体借助层次技能树，通过连续决策逐步发现并按需加载工具；动态加载与 ReAct 推理交错进行，从而同时保留足够的推理空间并提高工具命中率。

# II. 相关工作（忠实压缩翻译）

## A. 从通用智能体系统到遥感任务自动化

以 LLM 为核心控制器构建自主智能体，已成为复杂任务自动化的一条主流路线。LLM 在其中充当统一决策中心，通过分解子目标、规划任务和协调外部工具调用来推进执行。ReAct 让模型交替产生推理轨迹和行动决策，使其能在动态环境中依据新信息不断更新计划。随后，Reflexion 引入语言形式的自我反思，让智能体总结失败轨迹并形成改进策略；Tree of Thoughts 则研究对中间推理路径进行显式搜索。

在这一通用范式推动下，遥感任务自动化逐步从单模型推断转向面向多任务交互的视觉语言模型系统。早期工作主要把 VLM 适配到遥感场景，用于图像描述、视觉问答和空间理解。RSGPT 构建高质量遥感图文数据并微调模型；GeoChat 加入区域级输入与空间坐标表示，以支持区域推理和视觉定位；EarthGPT 通过统一指令微调融合多源传感器数据；EarthDial 进一步处理多时相、多光谱和多分辨率数据；RemoteCLIP 和 SkySense 则探索遥感视觉语言基础模型与多模态遥感基础模型。不过，这些系统多数仍由指令直接驱动，主要解决单步或弱规划任务，对需要复杂流程控制和专业工具调用的应用支持有限。

为提高自动化程度，研究者开始构建以 LLM 为控制核心的遥感自主智能体。RS-Agent 验证了这一思路的可行性；Earth-Agent 集成 104 个领域工具，支持多模态、定量时空推理和科学分析；ChangeAgent 面向交互式变化分析；GeoLLM-Squad 让一个协调器把请求分解后交给多个专业智能体。Earth-Bench、GeoLLM-QA 和 ThinkGeo 等工作则提供了评测基准。

这些工作推动遥感从单步感知走向复杂工作流自动执行，但大多假定工具空间已经预先确定，并且在执行前静态可见。随着专业工具数量增加、任务链变长，这种固定暴露方式会带来高上下文负担和工具选择效率下降。本文因此进一步研究大规模遥感工具环境中的动态工具发现。

## B. 智能体工具的组织与检索

随着工具数量扩大，研究者从语义检索、结构化组织和动态生成等方向改进工具获取。ToolLLM 构建包含 16,000 多个真实 REST API 的 ToolBench，并训练 API 检索器；AnyTool 通过层次化 API 结构逐层缩小搜索范围；Re-Invoke 研究零样本工具调用改写；ToolGen 把工具选择视为生成式决策，并为工具加入专用 token。此类方法可以减轻上下文负担、提升选择效率，但本质上仍多依赖一次性检索，容易漏掉复杂长流程任务后续步骤所需的工具。

另一类研究显式组织工具之间的执行逻辑和输入输出依赖。Voyager 表明智能体可在开放环境中通过终身学习建立不断扩大的技能库；ToolNet 不再使用扁平列表，而是建立工具网络；Graph of Skills 和 SkillNet 等工作探索技能依赖、能力复用及长期演化。动态代码生成还允许智能体按需合成工具。

这些方法虽然改善了大规模工具空间的可扩展性，却仍主要把工具获取当作一次检索或按需生成的问题，缺少明确机制来刻画执行过程中不断变化的工具需求。长流程遥感任务要求智能体依据中间状态持续调整后续工具选择，因此工具获取更接近主动探索。本文据此把工具选择表述为在结构化工具空间内进行的主动探索：智能体在推理中逐步发现和获得工具，而不是在第一步作出一次静态决定。

# III. 方法

本文把遥感智能体解决任务的过程建模为结构化工具空间中的顺序决策问题，把信息展开、工具发现、工具执行和结果生成统一进同一策略空间。不同于被动工具选择，RS-Claw 把智能体定义为主动工具探索者。智能体可以依据当前任务，自主决定何时扩大可见工具空间、探索哪一部分工具信息，再继续推理和执行。

RS-Claw 包含三部分：统一的顺序决策建模、层次化技能树构建、渐进式披露策略。图 2 上半部分给出统一决策模型；下半部分展示智能体如何沿技能树主动执行探索动作，依次获得工具简介和完整执行文档，并动态扩大可调用工具集合。

## A. 统一的顺序决策建模

设用户问题为 \(x\)，大规模遥感工具库为：

\[
T=\{t_1,\ldots,t_N\}
\]

每个工具 \(t_i\) 都对应一份说明 \(d_i\)，介绍功能、输入和输出；所有完整工具说明构成 \(D=\{d_1,\ldots,d_N\}\)。遥感任务往往具有长流程依赖和异构的中间表示，后续决策取决于此前产生的观察结果。因此，解决问题不是一次匹配，而是随着中间观察不断演化的顺序决策过程。

作者把该过程写成部分可观察马尔可夫决策过程（POMDP）：

\[
\mathcal{M}=(Z,A,O,P) \tag{1}
\]

其中，\(Z\) 是不可直接看见的环境状态空间，包括真实遥感数据状态和工具执行后的环境状态；\(A\) 是动作空间；\(O\) 是观察空间；\(P(z_{k+1}\mid z_k,a_k)\) 是状态转移概率。第 \(k\) 步采取的动作是 \(a_k\)，环境返回的观察是 \(o_k\)。因为智能体看不到隐藏状态 \(z_k\)，它只能根据用户问题、当前可调用工具和执行历史作决定。于是第 \(k\) 步的统一决策状态定义为：

\[
h_k=(x,V_k,\tau_k) \tag{2}
\]

其中：

\[
\tau_k=(o_0,a_1,o_1,a_2,o_2,\ldots,a_{k-1},o_{k-1})
\]

表示第 \(k\) 次决策前的交互历史；\(o_0\) 是第一次决策前已有的初始上下文；\(V_k\subseteq T\) 是第 \(k\) 步能够直接调用的工具集合。只有某工具的语义说明已经出现在交互历史中，该工具才可调用：

\[
V_k=\{t_i\in T\mid d_i\in\tau_k\} \tag{3}
\]

智能体依据策略 \(\pi(a_k\mid h_k)\) 选择动作。执行后，环境转到下一隐藏状态并返回新观察。

> **零基础提示：POMDP 在这里不需要先学高等数学。**它只是把过程说清楚：AI 看不到世界的全部真实状态，只能根据“用户问题 + 已解锁工具 + 过去发生的事”决定下一步。

### Flat 是这个统一模型的一个受限特例

Flat 被动且静态地把全部工具说明 \(D\) 注入上下文：

\[
h_k^{\text{flat}}=(x,V_k,\tau_k),\quad o_0=D,\quad V_k=T \tag{4}
\]

全部工具从一开始就能调用，动作只有调用工具或回答：

\[
a_k^{\text{flat}}\in\{\operatorname{call}(t_i,\theta_i),\operatorname{answer}(y)\},\quad t_i\in V_k \tag{5}
\]

这里，\(\theta_i\) 表示调用参数；\(\operatorname{answer}(y)\) 表示输出最终答案并结束。该方式迫使智能体每一步都在大量工具说明的干扰下决策。

### RAG 也是一个受限特例

RAG 通过独立于智能体动作空间的外部相似度函数，先召回工具说明子集：

\[
h_k^{\text{RAG}}=(x,V_k,\tau_k),\quad
o_0=f_{\text{sim}}(x,D),\quad
V_k=\{t_i\mid d_i\in o_0\} \tag{6}
\]

智能体仍然只能调用候选工具或作答：

\[
a_k^{\text{RAG}}\in\{\operatorname{call}(t_i,\theta_i),\operatorname{answer}(y)\},\quad t_i\in V_k \tag{7}
\]

最初上下文和可调用集合都由外部检索器决定；智能体无法通过自己的动作主动扩大这个集合。

### RS-Claw 的主动范式

RS-Claw 把获得工具信息本身设为智能体可以决定的动作：

\[
h_k^{\text{active}}=(x,V_k,\tau_k),\quad V_k\subseteq T \tag{8}
\]

可选动作包括信息探索、工具执行和终止：

\[
a_k^{\text{active}}\in A_{\text{explore}}\cup
\{\operatorname{call}(t_i,\theta_i),\operatorname{answer}(y)\} \tag{9}
\]

一步执行后，观察可能是探索得到的信息，也可能是工具执行结果：

\[
o_k=
\begin{cases}
o_k^{\text{info}}, & a_k\in A_{\text{explore}}\\
o_k^{\text{exec}}, & a_k=\operatorname{call}(t_i,\theta_i)
\end{cases} \tag{10}
\]

与被动方法不同，工具信息观察会随主动探索积累进历史轨迹，使可调用集合 \(V_k\) 受智能体策略控制。

### 表 1：三种工具获取方式的核心区别

| 比较维度 | Flat | RAG | RS-Claw 主动探索 |
|---|---|---|---|
| 初始上下文 | 全部工具说明 | 外部相似度检索得到的子集 | 只有最少量的技能摘要 |
| 可调用工具 | 全局、静态、始终不变 | 局部、静态、始终不变 | 随历史轨迹自主动态扩展 |
| 单步动作 | 调用或回答 | 调用或回答 | 探索、调用或回答 |
| 单步观察 | 只有工具执行结果 | 只有工具执行结果 | 既有信息观察，也有执行结果 |
| 获取机制 | 强制一次性全局注册 | 与智能体动作无关的被动召回 | 智能体自主搜索 |

## B. 层次化技能树

在传统扁平结构中，智能体面对全部说明时没有清楚的搜索边界。受人类“从宏观意图到微观动作”的自上而下认知方式启发，作者构建层次技能树，为高维工具空间提供组织结构和局部展开的先验。

设技能节点集合为 \(S=\{s_1,\ldots,s_M\}\)。完整工具集 \(T\) 被划分到 \(M\) 个互不重叠的局部工具子空间 \(T_m\)，每个底层工具只属于一个父技能节点。整个工具空间进一步分成三个逐级展开的信息层次。

1. **技能摘要层。**用简短自然语言 \(\sigma(s_m)\) 描述每个分支的核心能力边界，为全部工具提供宏观索引。它以很低的 token 成本构成初始上下文，帮助模型先做粗筛，避免进入完全无关的领域分支。
2. **工具目录层。**进入某个技能分支后，智能体看到分支内各候选工具的简短说明 \(\psi(t_i)\)。这一层保留核心功能、适用边界和高层输入输出关系，但隐藏代码参数细节。模型可以先在相似工具之间辨别用途，确定目标后再进入下一层。
3. **工具文档层。**位于树的叶子，包含完整工具说明 \(d_i\)、严格 API 签名和参数规范，用于真正调用工具。此类机器可读说明往往很长，因此只在调用意图明确后懒加载。

这不是简单把工具分组，而是符合“先确定能力范围—再筛选具体工具—最后读取执行参数”的渐进搜索路径。探索粒度逐层变细，无关语义噪声被隔离和过滤。

> **零基础类比：**第一层像商场楼层牌（餐饮、服装、影院）；第二层像进入餐饮层后看到店铺列表；第三层才是某家店的完整菜单和点餐规则。

## C. 渐进式披露策略

系统最初只把最上层技能摘要提供给智能体，底层工具均不可直接调用：

\[
o_0=\{\sigma(s_m)\}_{m=1}^{M},\quad V_1=\varnothing \tag{11}
\]

RS-Claw 的探索动作有两类：

- \(\operatorname{skill}(s_m)\)：展开技能节点 \(s_m\) 下所有候选工具的简介 \(\psi(t)\)；
- \(\operatorname{doc}(t_i)\)：展开具体工具 \(t_i\) 的完整执行文档 \(d_i\)。

执行 `skill` 时，系统只返回该分支的工具简介：

\[
o_k^{\text{info}}=\{\psi(t)\mid t\in T_m\}
\]

它帮助缩小范围，但不会立即赋予调用权限，所以 \(V_{k+1}=V_k\)。只有继续执行 `doc`，具体工具的完整说明才写入历史，该工具也在下一步进入可调用集合：

\[
V_{k+1}=V_k\cup\{t_i\}
\]

普通工具调用和最终回答不会解锁新工具。换句话说，技能层和目录层返回中间信息观察；只有具体工具文档被主动读取后，工具才真正可调用。工具发现因此从一次性静态注入，变成由智能体自己推进的连续过程。

每一步只展开当前任务相关的局部信息，于是上下文负担从全局 \(O(N)\) 降为局部 \(O(K)\)，其中 \(K\ll N\)，且由策略动态决定。更重要的是，无关信息不会大量涌入上下文，因而可以减少上下文污染和 token 消耗。

# IV. 实验

## A. 实验设置

### 基准

作者使用 Earth-Bench。它原有 248 道遥感智能体分析题，涵盖光谱指数计算、时间序列分析、变化检测、建筑和目标检测、多源数据融合等任务。

评测分两种模式：

- **自主规划模式（AP）**：题目不直接给步骤，智能体必须自己决定调用哪些工具及调用顺序。
- **指令遵循模式（IF）**：外部给出推理步骤，智能体负责把步骤转换为正确工具调用。

由于公开基准没有提供 ChangeOS 所需的深度学习模型或预计算输出，作者排除了与 ChangeOS 相关的 14 道题（编号 216–225、242–245），最终所有指标均在 **234 道题**上计算。

### 基线

1. **Flat**：Earth-Agent 官方方式，把全部工具以无结构扁平列表写进系统提示。
2. **RAG**：每道题开始前，根据问题语义检索最相关的 19 个工具，并强制加入文件枚举工具 `get_filelist`。

三种方法均基于 ReAct，通过 Thought–Action–Observation（思考—行动—观察）循环完成多步工具推理。

### 模型与技能树

实验使用 GPT-5、DeepSeek-V3.1 和 Qwen3-32B。为了控制成本，消融实验只使用 Qwen3-32B。工具按 Earth-Agent 官方分类组织为五个技能：**Index（指数）、Inversion（反演）、Perception（感知）、Analysis（分析）、Statistics（统计）**。

### 指标

准确性分为端到端指标和步骤级指标：

- **Accuracy**：最终选择题答案是否正确；
- **Efficiency**：模型工具调用数与标准轨迹调用数之比；
- **Tool-Any-Order**：不考虑顺序，标准答案需要的工具有多少被模型调用；
- **Tool-In-Order**：标准工具有多少按正确相对顺序出现；
- **Tool-Exact-Match**：从开头起，预测工具序列与标准序列在相同位置严格匹配的程度；
- **Parameters**：工具名及全部参数同时精确匹配的程度。

上下文开销用“每题平均输入 token”和“每轮平均输入 token”衡量。

RS-Claw 在三个模型、两种模式的最终准确率和主要工具匹配指标上都高于两种被动基线。模型能力越弱，改进幅度越大：Qwen3-32B/AP 比 Flat 高 12.45 个百分点，而 GPT-5/AP 高 3.00 个百分点。这说明渐进式披露可以缓解推理空间不足和注意力失焦，对更容易受上下文负担影响的模型帮助尤其明显。

RAG 在所有模型上的准确率均低于 RS-Claw。原因在于 RAG 把工具选择交给外部嵌入模型，LLM 无法根据推理途中出现的新结果主动调整工具范围，难以覆盖后续步骤需要的关键工具。Flat 和 RAG 因而位于权衡的两端：前者工具完整但上下文过载，后者上下文较轻但工具覆盖不全；RS-Claw 试图在两者之间取得平衡。

相较 Flat，RS-Claw 大幅减少每题输入 token。Qwen3-32B/AP 的压缩率约为 86%，每轮 token 下降约 81%。不同模型的节省程度不同：GPT-5 的每题压缩率约 20%，远低于 Qwen3-32B。

## C. 消融实验

作者用两种变体验证设计中的两个关键因素。

- **Random**：仍用三层树和两步披露，但把工具随机分配到五个技能节点，破坏语义一致性。
- **2layers**：移除技能摘要层，把全部工具名称和简介按类直接放进系统提示；模型只需执行 `doc` 读取详细文档。它介于 Flat 和完整 RS-Claw 之间。

### 表 4：消融准确性（Qwen3-32B，%）

| 方法 | Accuracy AP | IF | Tool-Any-Order AP | IF | Tool-In-Order AP | IF |
|---|---:|---:|---:|---:|---:|---:|
| Random | 23.18 | 25.32 | 44.21 | 48.13 | 31.44 | 37.93 |
| 2layers | 25.75 | 25.32 | **58.07** | **62.50** | **43.16** | **50.37** |
| RS-Claw | **33.05** | **29.18** | 50.22 | 60.77 | 32.06 | 44.91 |

### 表 5：消融上下文开销

| 方法 | 每题 AP | 每题 IF | 每轮 AP | 每轮 IF |
|---|---:|---:|---:|---:|
| Random | 100,903 | 139,269 | 6,337 | 7,525 |
| 2layers | 82,896 | 106,165 | 6,415 | 7,196 |
| RS-Claw | **70,759** | **97,325** | **5,951** | **6,309** |

Random 在 AP 模式下比 RS-Claw 低 9.87 个准确率百分点，每题 token 高 43%。随机分组使技能摘要的语义先验失效，智能体必须反复探索错误分支，徒增上下文并降低准确率。这说明有意义的语义组织不可缺少。

2layers 直接暴露全部工具名，所以工具发现指标甚至高于 RS-Claw；但 Qwen3-32B 的推理空间被压缩，最终准确率反而更低。AP 模式中，2layers 的 Tool-Any-Order 为 58.07，高于 RS-Claw 的 50.22，但 Accuracy 只有 25.75，低于 RS-Claw 的 33.05。这说明“看见更多工具”并不自动带来“答对更多问题”。技能摘要层是控制上下文规模的重要屏障。

两组消融共同说明：语义合理的技能树组织，以及保留技能摘要层的渐进式披露，二者都不可缺少。

## D. 工具扩展性实验

作者使用 Qwen3-32B，从两个方向扩大工具库。

### 1. 同领域扩展

实验从完成任务所需的最小工具集 GT 开始，每次加入 20 个同领域但无关的遥感工具，直到包含全部 104 个工具，共形成六个规模档位。

当只有 GT、完全没有冗余时，Flat 的准确率略高、每题 token 略低，因为完整注册此时没有引入语义噪声，直接看见工具也省去了技能导航。这个结果说明 RS-Claw 的优势并非无条件成立，而是来自工具规模扩大后产生的上下文负担。

随着工具增加，差距迅速反转：RS-Claw 的准确率大体稳定，Flat 持续下降；从 GT+20 起 Flat 低于 RS-Claw，之后差距总体扩大。Flat 的 token 近似线性增长，AP 模式增幅超过 1,100%，而 RS-Claw 只缓慢增长。渐进式披露把可见工具信息限制在局部范围，因此能抑制候选干扰和上下文膨胀。

### 2. 跨领域扩展

作者在 104 个遥感工具之外，依次加入 API-Bank 中 75 个通用工具（总计 179 个，stage1），再加入 ToolBench 中 55 个广告、商业和音乐等工具（总计 234 个，stage2）。这些新增工具对 Earth-Bench 都没有实际用途，属于纯粹的跨领域语义噪声。

加入跨领域工具后，两种方法的准确率都没有明显崩溃。一个可能解释是，这些工具在语义上离遥感任务很远，模型较容易过滤。不过上下文开销差距仍很明显：Flat 的每轮 token 随总工具数线性增长，RS-Claw 基本稳定，因为无关工具说明从未进入实际上下文。

同领域和跨领域实验共同表明，在两种常见的工具库扩展场景下，渐进式披露的准确率下降相对缓慢，上下文增长远低于 Flat，因此更适合工具持续增长的开放环境。

# V. 讨论

## A. 局限性

虽然 RS-Claw 在多个模型和评测模式中都相对两种基线取得了一致改进，但仍有若干局限。

第一，当前技能树的五个类别直接继承自 Earth-Agent 官方工具分类，是静态、人工预定义的拓扑。工具库大幅变化或迁移到新领域时，需要领域专家重新设计树；各技能节点的粒度也不均衡。

第二，渐进式披露虽然把工具探索纳入智能体的决策空间，但探索路径质量从根本上取决于底层 LLM 的规划能力。模型规划能力不足时，仍可能作出次优的探索决策。

第三，`skill → doc` 两步探索会增加交互轮数。渐进式披露的优势来自大工具库造成的上下文负担；工具库很小时，额外探索开销可能超过收益。

第四，本文只在 Earth-Bench 和三个模型上验证，能否推广到更多领域和更大工具库仍需研究。

## B. 与其他工作的联系

### 1. 与现有遥感智能体的关系

RS-Agent、Earth-Agent、ChangeAgent 和 GeoLLM-Squad 等工作把遥感从单步感知推进到复杂工作流自动化，但普遍隐含假设：工具空间在执行前完全可见，智能体在静态预定义工具集上规划和调用。RS-Claw 在 ReAct 基础上进一步把工具获取本身放入决策空间，让可调用集合在推理中动态演化，无需修改底层模型即可为长流程任务提供更可扩展的工具管理方式。

### 2. 与通用工具选择和组织方法的关系

无论 ToolReAct、Gorilla、ToolLLM 等检索方法，还是 AnyTool、ToolNet、Graph of Skills 等层次组织方法，都有一个共同限制：获取工具的触发逻辑由外部模块控制，与智能体的推理过程分离。前者在任务开始前用外部检索器一次性锁定候选集合；后者虽有层次结构，但层次展开通常由预设程序逻辑驱动。

RS-Claw 的根本区别是把工具信息获取完全内化为智能体自己的决策变量。探索路径由策略输出，可调用集合随中间推理状态持续演化，使智能体能在长流程任务中按实际需要动态调整探索方向。

## C. 意义

1. **对遥感领域的意义。**遥感任务常有长工作流、工具说明高度相似和中间状态复杂等特点，正是完整工具注册最容易遇到瓶颈的场景。RS-Claw 针对这些痛点设计，为大规模专业工具库上的长流程任务自动化提供了一条可行路径。
2. **实践意义。**RS-Claw 完全工作在工具端架构层，不需要微调模型，可作为即插即用的上下文管理策略接入 ReAct 智能体。实验说明，降低推理成本和维持任务质量并非必然冲突；工具扩展实验中，上下文开销随工具库增长仍近似稳定。
3. **理论意义。**本文在统一的顺序决策框架中描述 Flat、RAG 和主动探索，把工具信息获取与工具执行明确区分为两类观察。工具获取不是一次静态决定，而是随推理状态变化的动态过程。

# VI. 结论与未来工作

## A. 结论

本文针对遥感智能体面对大规模工具库时的上下文瓶颈，提出基于层次技能树的渐进式主动工具探索机制 RS-Claw。作者把工具信息获取设为智能体的自主决策变量，通过统一的 POMDP 顺序决策建模，把工具探索动作纳入策略空间。

三层技能树与渐进式披露策略使工具可以按需加载，有效压缩工具上下文。Earth-Bench 实验中，RS-Claw 在三个模型和两种评测模式下优于 Flat 和 RAG 两种被动基线；模型能力越弱，改进越明显，最高上下文压缩率达到 86%。消融实验验证了语义组织结构与三层渐进披露机制的必要性，工具扩展实验验证了可扩展性。

作为一种轻量、即插即用的工具组织策略，渐进式披露为大规模工具空间中的智能体上下文管理提供了新视角。

## B. 未来工作

RS-Claw 证明了在遥感场景中进行渐进式主动工具探索的有效性。为了让这种工具空间管理方式更自适应、更可扩展并适用于更多领域，作者提出四个方向。

1. 根据工具说明的语义嵌入自动聚类，替代人工分类；加入自适应拆分和合并，让技能树随工具库增长自动调整拓扑。
2. 构建渐进式披露交互范式下的探索轨迹数据，通过监督微调或强化学习优化模型在层次结构中的探索策略。
3. 引入探索预算或动态路由，根据任务复杂度自适应调整披露深度，在准确率和开销之间取得更好平衡。
4. 把方法扩展到更多垂直领域、更大规模工具库和更多模型上进行验证。

# 给零基础读者的第一遍总结（非论文原文）

这篇论文要解决的矛盾可以压缩成一句话：

> **工具全给 AI，看得太多会乱；只提前搜几个，又可能不够用。RS-Claw 让 AI 在做题过程中自己逐层找工具。**

完整流程是：

1. 用户给一道遥感问题；
2. AI 最初只看到五类技能的简短介绍；
3. AI 用 `skill` 进入最相关的一类；
4. AI 从该类的工具简介中选一个，再用 `doc` 阅读完整参数说明；
5. 这个工具此时才被解锁，AI 用 `call` 执行；
6. AI 根据结果继续探索、调用，最后作答。

第一次阅读时，请先抓住三件事：

- **核心问题**：大型工具库会占满上下文并造成语义干扰。
- **核心办法**：技能摘要 → 工具目录 → 完整文档，逐层按需展开。
- **核心证据**：在 234 道 Earth-Bench 题上，RS-Claw 的主要准确率优于 Flat 与固定 Top-19 RAG；但每题总 token 并非在所有模型上都最低，而且论文自己承认技能树仍靠人工构建、验证基准也只有一个。

不要急着背 POMDP 公式。先确认自己能解释 Flat、RAG 和 RS-Claw 三者的差别，再回头看公式；公式只是把这个差别写得更严格。
